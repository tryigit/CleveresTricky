# Keybox Manager

**Sprache:** [English](../../../security/KeyboxManager.md) | [Türkçe](../../tr/security/KeyboxManager.md) | [简体中文](../../zh-CN/security/KeyboxManager.md) | [Español](../../es/security/KeyboxManager.md) | **Deutsch** | [Русский](../../ru/security/KeyboxManager.md) | [Bahasa Indonesia](../../id/security/KeyboxManager.md) | [हिन्दी](../../hi/security/KeyboxManager.md) | [العربية](../../ar/security/KeyboxManager.md)

Lädt, verifiziert, wählt und überwacht autorisiertes Attestation-Key-Material in Legacy-, XML- und CBOX-Form. App-Regeln können spezifische Dateien referenzieren; Remote-Daten bleiben bis zur lokalen Prüfung untrusted.

Private Key muss Leaf Certificate entsprechen; Algorithmus, Chain, Datum, Duplikate/Ambiguität und Revocation werden geprüft. Gültiges Schlüsselmaterial wird beim Systemstart ohne Warten auf das Netzwerk sofort aktiviert. Bei aktiviertem Automatic Keybox Check wird die Revocation-Prüfung im Hintergrund durchgeführt; bei deaktivierter Prüfung wird auch benutzerdefiniertes oder widerrufenes Material zugelassen. Ein fehlerhafter Pool wird komplett verworfen. Jede gespeicherte Keybox kann in der WebUI deaktiviert werden, ohne sie zu löschen; der deaktivierte Eintrag bleibt in der Liste, verlässt aber sofort den aktiven Pool und wird bei der Auswahl übersprungen. Der Zustand liegt in einer Klartextdatei `disabled_keyboxes` im Konfigurationsverzeichnis, eine `Bereich:Dateiname`-Kennung pro Zeile (`keyboxes:keybox2.xml`, `root:keybox.xml`); da er dateibasiert ist, übersteht er Modul-Updates, kann manuell oder über Magisk-Werkzeuge gepflegt werden, und das Löschen der Datei aktiviert alle Keyboxen wieder. Eingefügte oder abgelegte Keyboxen werden unter dem angegebenen Namen gespeichert, oder als `keybox.xml`, wenn kein Name angegeben wurde; ist der Name belegt, wird automatisch der nächste freie Name (`keybox2.xml`, `keybox3.xml`, ...) gewählt, sodass eine vorhandene Keybox nie stillschweigend ersetzt wird.
